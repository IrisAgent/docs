## **Introduction**

\
IrisAgent provides AI-powered answers to support tickets from internal knowledge base in Confluence using the Atlassian Confluence integration.

## **Before you start**

- An IrisAgent account with your ticketing provider already connected.
- A Confluence Cloud site (your site address ends in `.atlassian.net`).
- An Atlassian user who can read the Confluence spaces you want IrisAgent to use. A dedicated service user is recommended (see [Permissions of the Atlassian Token](#permissions-of-the-atlassian-token)).

## **Step 1: Create a scoped Atlassian API token**

1. Signed in as that Atlassian user, open your Atlassian account settings, go to **Security**, then **API tokens**, and create an API token with scopes. Here are [the steps to create the token](https://support.atlassian.com/atlassian-account/docs/manage-api-tokens-for-your-atlassian-account/).
2. Choose **Confluence** as the app and add these scopes:
   - `read:confluence-content.all`
   - `read:confluence-content.summary`
   - `read:confluence-space.summary`
   - `read:confluence-props`
   - `search:confluence`
3. Copy the token. You will paste it into IrisAgent in Step 3.

## **Step 2: Find your Cloud ID**

1. Open `https://{your-site-name}.atlassian.net/_edge/tenant_info` in your browser.
2. The page shows a line like `{"cloudId":"1234abcd-12ab-34cd-56ef-1234567890ab"}`. Copy just the `cloudId` value (the UUID). If you paste the whole line, IrisAgent extracts the UUID for you.

## **Step 3: Connect Confluence in IrisAgent**

1. Login to the [IrisAgent dashboard](https://web.irisagent.com/).
2. In the left navigation, open **Data Sources** and select **Knowledge Bases**.
3. On the Confluence card, click **Connect**. The **Connect Confluence** screen opens.
4. Fill in the four fields:
   - **Confluence API Token**: the token from Step 1.
   - **Email Address**: the email of the Atlassian user who created the token.
   - **Subdomain**: your site name only, without `https://` and without `.atlassian.net`. For `https://acme.atlassian.net`, enter `acme`.
   - **Cloud ID**: the UUID from Step 2.
5. Click **Connect**. The Confluence card now shows **Connected**, with the number of synced articles underneath.

IrisAgent syncs Confluence pages and blog posts. Page labels are kept as article tags, and pages edited in Confluence are picked up on the next sync.

<Note>
  The Confluence card connects Confluence Cloud sites. For an Atlassian Server or Data Center instance, use the **Atlassian/Jira Server** card under **Data Sources → Development**, or contact IrisAgent support.
</Note>

## **Step 4: Select which Confluence spaces IrisAgent reads**

1. When creating the token in Step 1, use an Atlassian user who can only read the relevant spaces.
2. On the **Data Sources → Knowledge Bases** page, click the Settings gear icon on the connected Confluence card.
3. In the side panel, under **Confluence Spaces**, select the spaces you want IrisAgent to read (each shows its article count), then click **Apply**. **Select All** and **Select None** are available. If no space is selected, all spaces the token can read are included.

## **Step 5: Test it**

Open **Chatbot** under **AI Products** and ask a question your Confluence pages answer. The answer lists the Confluence page it used under **Sources**.

## **Details on IrisAgent's Atlassian Connection**

IrisAgent only ingests data from Atlassian from the last 3 months (can be configured). It make POST and GET API calls to fetch data while ensuring that the Atlassian's rate limits are not exceeded. The frequency of API call can be configured based on customer's preference.

### **Permissions of the Atlassian Token**

The Atlassian token generated by a user has the same access level as that user’s permissions within jira. It is recommended that a service user be created and that user’s token be entered in the IrisAgent dashboard, so that permissions can be easily granted/revoked as and when new functionality is introduced.

### **Token scopes needed for Confluence**

IrisAgent uses this integration to automatically suggest articles and resolutions from Confluence that match a new support case and assist both support reps and customers in finding faster resolutions. The API token needs these Confluence scopes, which let IrisAgent read and search pages and blog posts:

1. `read:confluence-content.all`
2. `read:confluence-content.summary`
3. `read:confluence-space.summary`
4. `read:confluence-props`
5. `search:confluence`

### **Granting Access only to either Jira/Confluence**

1. Create a service user who has access only to the feature you want to use. E.g. : A service user with access restricted only to Confluence.
2. If the service user has access to one of Jira/conlfluence, please ensure that all permissions required within that section are met.
3. Generate a token for this service user and follow the same connection procedure by visiting **Data Sources → Knowledge Bases** as mentioned above.

### **Data Governance and Security**

Data between customer environments and IrisAgent’s systems is always encrypted at rest and during transmission, authenticated at each endpoint, monitored for integrity, and protected by enterprise-grade security protocols and operational best practices.

- IrisAgent removes PII data and does not store any PII data on our servers.
- Data is encrypted in transit and at rest. IrisAgent uses industry-standard encryption protocols to ensure that your data is secure.
- You can ensure that the integration with Atlassian is only for specific projects and spaces, so that no data is shared outside of the scope of your support operations.
- IrisAgent only ingests data from Atlassian from the last 3 months (can be configured). It makes API calls safely to fetch data while ensuring that the Atlassian's rate limits are not exceeded. The frequency of API call can be configured based on customer's preference.
- IrisAgent does not share any data with third parties.
- IrisAgent is SOC 2 Type II compliant and GDPR compliant.
